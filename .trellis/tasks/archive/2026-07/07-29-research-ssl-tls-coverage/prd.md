# 调查 SSL TLS 检测覆盖与缺口

## Goal

用可复现证据回答 AnchorScan 当前对 SSL/TLS 的识别和漏洞检测覆盖到什么程度，并形成可独立实施的后续规则清单。

## Requirements

- 区分 HTTPS/Web 指纹识别、TLS 协议检查、证书检查和具体 TLS 漏洞检测，不得混为“支持 SSL”。
- 盘点当前 Nmap/NSE、httpx、Nuclei tags 和配置映射的实际调用路径。
- 以项目锁定或支持的工具/模板版本为准，核验规则是否存在、是否默认执行及是否被忽略。
- 对每个缺口记录目标类型、触发条件、主动���、安全风险、预期证据和误报边界。
- 输出研究文档及按优先级排序的后续任务建议；调查本身不修改扫描规则。

## Non-goals

- 不在证据未收敛前宣称“完整覆盖”。
- 不在本任务中启用侵入性、爆破或可能造成服务中断的检查。
- 不把 Spark 规则纳入本任务。

## Acceptance Criteria

- [x] 研究文档分别列出识别、配置、证书和漏洞检测的已覆盖/未覆盖/条件覆盖项。
- [x] 每项结论含代码或配置位置、工具/模板版本及可复现验证方式。
- [x] 风险较高的候选规则标明授权与安全限制。
- [x] 后续规则工作被拆为可独立验收的任务建议，而非直接混入调查。
