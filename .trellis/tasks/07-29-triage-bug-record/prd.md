# 审阅、归类并规划 bug 记录

## Goal

将 `bug记录.md` 中混合记录的缺陷、能力缺口、产品需求和工程疑问整理为一组无重复、证据充分、可独立验收的工作项；复用已有任务，避免重复修复。

## Source scope

本任务覆盖 `bug记录.md` 当前记录的八项内容：

1. GitHub Actions 是否需要运行当前全部检查。
2. Dameng 候选探测日志过多。
3. Console 时间应按上海时间展示。
4. SSL/TLS 检测覆盖不明确。
5. Spark 检测规则缺失。
6. 报告中的 `tcpwrapped` 淹没已识别服务。
7. 项目内置 Nuclei 模板是否仍有残留。
8. 对 Nmap 未识别服务增加通用指纹增强。

## Requirements

- 保持当前 PR、Release 和真实工具实验室的测试类型及门禁，不为重复 host 验证另建优化任务；后续只有在运行时长或费用数据证明有必要时再评估。
- 默认自动扫描规则只允许按 tags 调度 Nuclei，不允许 `service-tags.yaml` 使用 `template:`；后续任务移除默认规则的模板字段、路径解析、执行分支及锁定该能力的测试。
- 操作者单工具功能继续允许显式 `--template`；该能力与默认自动扫描规则保持分离。
- Web Console 固定使用 `Asia/Shanghai`，格式为 `YYYY-MM-DD HH:mm:ss.SSS UTC+8`；扫描详情与单工具实时输出必须一致。
- 数据库和 API 继续使用 UTC/RFC3339，展示转换不得改变排序、轮询或事件增量语义。
- 报告默认完整展示所有原始扫描事实，不默认隐藏 `tcpwrapped`、`unknown` 或空服务名。
- 报告提供“一键排除未识别服务”；展示层可将 `tcpwrapped`、`unknown` 和空服务名归入“未识别”快捷分组，但底层查询仍保留原始值集合。
- 服务筛选器展示当前 Run 的服务类型及数量；聚合口径应用其他筛选条件，但不应用当前服务筛选，避免选项自我消失。
- 每条原始记录必须映射到以下一种结果：复用现有任务、新建独立任务、建立研究任务、记录为已解决，或经用户确认后不做。
- 对已确认问题记录可复现证据、影响、优先级和可测试的验收边界。
- 不得为已有任务覆盖的内容创建重复任务。
- 已解决事项必须关联解决提交或验证证据；过时任务必须在启动前修订或归档，不能按失效方案执行。
- 新任务按可独立验证的交付物拆分；依赖顺序写入子任务要求，不依赖父子目录隐式表达。
- 扫描能力扩展必须先明确授权、安全、超时、请求上限、误报和证据契约。
- CI 优化不得通过删除不同测试层来掩盖构建、打包、浏览器、依赖安全或真实工具边界上的回归。
- 本任务只负责调查、决策收敛和任务规划，不修改产品代码。

## Constraints and non-goals

- 保留用户及其他并发 Agent 的未提交改动，不清理或回滚无关文件。
- 不删除历史 Run、历史 artifact 或其中记录的旧模板路径。
- 不在持久化层删除或改写 `tcpwrapped`、`unknown`、空服务名等原始扫描事实。
- 不把数据库和 API 的 UTC 时间改存为上海时间；时区属于展示契约。
- 不在本任务内直接启动任何修复子任务；规划完成后需单独获得实施批准。

- [ ] 最终任务树和执行顺序经用户审阅批准后，才允许进入实施阶段。
