# 达梦数据库（DM7/DM8）预设账户、初始口令与弱口令研究

核查日期：2026-08-04。范围是达梦数据库服务器及随附管理/运维身份；不把第三方 Docker 镜像、样例连接串或扫描器字典误写成达梦软件发行版的出厂事实。

## 结论（先读此处）

1. **当前可访问的达梦 DM8 官方文档明确否定了“核心数据库安装后有一组可普遍使用的固定出厂口令”的说法。** 文档称安装时会预设管理账户，但“用户需要基于 DM 默认口令策略自行设置各个管理用户的口令”。因此，`SYSDBA/SYSDBA` 和 `SYSDBA/SYSDBA001` 都**不是可对任意 DM8 实例断言的官方固定默认凭证**。
2. `SYSDBA` 是真实且预设的数据库管理员账户；还应覆盖 `SYSSSO`、`SYSAUDITOR`，以及仅四权分立时的 `SYSDBO`。`SYS` 是预定义内部对象所有者，官方明确说它不能登录，不能作为弱口令候选。
3. `SYSDBA/SYSDBA`：存在于旧安装、旧教程、测试/镜像或后来人工设置的可能性很高，且本仓库旧设计文档曾把它当作检测值；但本次**没有获得 DM7/DM8 达梦官方安装资料证明它是某一正式发行版的出厂初始值**。对未知目标只可作为经授权的历史弱口令候选，不能报告成“DM8 官方默认”。
4. `SYSDBA/SYSDBA001`：公开第三方 Docker 安装记录声称其为某 DM8 Docker 环境的值，但本次没有取得该镜像的达梦官方发布页、镜像清单或官方部署文档来证明适用范围。它的证据更弱，不能升级为产品出厂事实。
5. “密码不可设置为 `SYSDBA`”并非用户名保留字导致的神秘限制。当前 DM8 默认口令策略值为 15，明确禁止口令与用户名相同，且要求至少一个大写、一个小写和一个数字；`SYSDBA` 同时违反这些要求。策略可被管理员改动或被用户级策略覆盖，所以应表述为**默认策略下不允许**，而不是所有版本/所有策略绝对不允许。

**风险等级：高（条件成立时）。** 如果任一远程可达实例实际接受下表中的高权限组合，影响为完全数据库管理、数据读取/改写、用户及配置控制。风险等级描述的是“认证成功”的后果，不是对每个达梦安装均存在默认口令的断言。

## 证据标准

- **强**：达梦官方 `eco.dameng.com` 文档直接陈述，且版本/组件范围明确。
- **中**：达梦官方材料直接支持账户或规则，但不提供具体口令或不能定位到 DM7 小版本。
- **弱**：可访问的第三方部署记录/样例；只作为候选线索，不是厂商出厂证明。
- **未证实**：本次未找到可核验的一手材料；不应纳入“官方默认口令”结论。

## 官方一手证据

### DM8 的预设账户和初始化规则

达梦官方 DM8《安全管理 - 用户标识与鉴别》在“三权分立”章节写明：安装过程中预设数据库管理员 `SYSDBA`、安全员 `SYSSSO`、审计员 `SYSAUDITOR`，且**用户需要基于 DM 默认口令策略自行设置各个管理用户的口令**。四权分立时还预设对象操作员 `SYSDBO`。同页说明 `SYS` 仅保存系统内部对象，“并非数据库管理员，也无法进行登录”。这是本研究对当前 DM8 的最高强度证据。

来源：[达梦官方《DM8 安全管理 - 用户标识与鉴别》](https://eco.dameng.com/document/dm/zh-cn/pm/identification-authentication.html)（章节 2.1.1、2.1.2；页面核查时标注“上次更新：2026-08-04”）。

这也区分了两个经常混淆的对象：

- 数据库账户：`SYSDBA` / `SYSSSO` / `SYSAUDITOR` /（四权分立）`SYSDBO`；是本节的认证对象。
- 操作系统账户：官方 DM8 安装手册示例建议创建 `dmdba` 用户和 `dinstall` 组，并要求执行 `passwd dmdba` 由系统交互设定口令。它不是数据库实例登录账户，也没有官方固定口令。

来源：[达梦官方《DM8 安装手册 - 安装及卸载》](https://eco.dameng.com/document/dm/zh-cn/pm/install-uninstall.html)（2.2.1.2“创建安装用户”）。

### 为什么默认策略拒绝 `SYSDBA` 作为密码

同一份官方 DM8 安全文档第 2.2.2 节规定：

- `PASSWORD_POLICY 15`：口令不得与用户名相同；长度不小于 `PWD_MIN_LEN`，最长 48 字节，且至少含一位大写、一位小写和一位数字；
- `PASSWORD_POLICY 31`：在 15 的基础上还要求至少一个标点符号；
- 系统参数 `PWD_POLICY` 的缺省值为 **15**；未在 `CREATE USER` 指定策略时使用该默认策略。

因此 `SYSDBA` 对用户 `SYSDBA` 至少违反“不得同名”、小写和数字要求。`SYSDBA001` 虽有大写和数字，**仍没有小写**，所以在这里记录的当前默认策略 15 下也不符合。文档同时表明策略可通过 `PASSWORD_POLICY`/`PWD_POLICY` 配置，故不能据此反推所有历史版本或被放宽策略的实例一定拒绝它。

来源：[达梦官方《DM8 安全管理 - 用户标识与鉴别》](https://eco.dameng.com/document/dm/zh-cn/pm/identification-authentication.html#2.2.2%20%E5%8F%A3%E4%BB%A4%E7%AD%96%E7%95%A5)（2.2.2）。

## 对两个重点组合的裁定

### `SYSDBA/SYSDBA`

- **用户名真实：是。** DM8 官方明确将其列为安装预设数据库管理员。
- **“官方出厂初始密码为 SYSDBA”：对当前 DM8，否。** 官方要求用户在安装中自行按默认口令策略设定；且默认策略明令禁止用户名相同。 
- **DM7：未决。** 本次未获得可公开访问、可定位版本和安装介质的 DM7 官方手册/部署资料来确认或排除某历史构建的行为。不能把 DM8 的现行文档倒推为所有 DM7 构建。
- **安全测试意义：有，但限定。** 仅作为授权历史弱口令测试；认证成功应以实际服务器响应为准并按高危处理。

### `SYSDBA/SYSDBA001`

- **用户名真实：是。** 如上。
- **“DM8 通用官方出厂初始密码”：本次不能证实，不能采信。** 它与当前官方默认策略 15 的小写字母要求也不一致。
- **为何仍会出现：** 更可能是旧发行/测试数据、第三方 Docker 包装层的默认环境变量、教程或部署者设置，而非可泛化的 DM8 核心安装规则。这个解释是推断，不是厂商确认。
- **第三方线索（非一手，不能单独作为结论）：** 搜狗索引到的 CSDN 页面片段称“DM8(docker安装，默认账号密码 SYSDBA/SYSDBA001)”。原页面为 [《达梦数据库基础知识(三)》](https://blog.csdn.net/) 的搜索结果，未能在本次核查中取得稳定、可定位的文章 URL、镜像标签和厂商来源，因此只记作弱线索而非引用依据。

## 管理工具、运维与审计边界

- **DM Manager / Console / DIsql：** 本次官方资料只证明 DM 客户端可以使用数据库账户登录（例如官方 Go 编程指南样例使用 `SYSDBA` 和一个显式样例口令）。样例口令不是默认口令；没有发现独立于数据库实例的“DM Manager 出厂管理员账号”。
- **本机 OS 认证：** DM8 可将 OS 组 `dmdba|dmsso|dmauditor` 分别映射为 `SYSDBA|SYSSSO|SYSAUDITOR`，但需要 `ENABLE_LOCAL_OSAUTH=1`，并要求把 OS 用户加入对应组。这是另一条认证路径，不应被误报为网络口令登录或固定密码。
  来源：[达梦官方《DM8 安全管理 - 用户标识与鉴别》](https://eco.dameng.com/document/dm/zh-cn/pm/identification-authentication.html)（2.3.2.1）。
- **服务暴露：** 默认端口常见为 5236，但端口、是否启用远程监听、认证策略和部署包装均可改变；端口识别不构成凭证存在证据。

## 建议的合规核验方式

1. 对已授权资产，从 CMDB/安装记录、镜像 digest、`dm.ini`、`V$PARAMETER` 中确认产品版号、安装方式、`PWD_POLICY`/`PWD_MIN_LEN` 和是否启用 OS 认证；不要凭端口或品牌猜密码。
2. 清点 `SYSDBA`、`SYSSSO`、`SYSAUDITOR`，并在安全版四权分立场景清点 `SYSDBO`；确认每个预设管理账号都有唯一、保管于密码库的高强度口令，或按最小权限禁用/限制。
3. 对遗留环境，若变更/镜像证据明确显示历史 `SYSDBA/SYSDBA` 或特定包装层 `SYSDBA/SYSDBA001`，再在授权、限速、审计条件下进行一次认证验证；认证失败不能证明没有其他弱口令。
4. 审计 `ENABLE_LOCAL_OSAUTH` 和 `dmdba`/`dmsso`/`dmauditor` 组成员，因为该路径不依赖远程数据库密码。

## 未解决问题

1. 需要达梦官方 DM7 安装手册或对应安装包内说明，按**精确小版本和安装方式**核验 DM7 是否曾自动写入 `SYSDBA/SYSDBA`；本次没有足够一手证据，结论保留。
2. 需要达梦官方 Docker/容器镜像仓库、镜像标签、entrypoint 或部署指南，核验 `SYSDBA001` 是否为任一官方镜像的默认值、是否可由环境变量覆盖，以及 `SYSSSO`/`SYSAUDITOR`/`SYSDBO` 的容器初始化规则。
3. 当前在线官方 DM8 页面是滚动更新文档，未显示可复现的 DM8 小版本或 PDF 修订号；若用于合规报告，应归档访问日期、页面副本/哈希和目标安装介质版本。
4. 未找到达梦官方材料证明 DM Manager、Console 等管理工具有独立固定登录账号；目前最稳妥的结论是它们使用数据库账户或另行配置，仍需按具体组件版本核验。
